What was delivered

Phase 6.5 took BJP Technologies' public site from a services-only company page to a productized brand showcasing three live software products built in-house. The Products

What's now public on bjptechnologies.co.tz

PMS — Property Management Software

Tagline: Property management, finally simple.  Slug: pms · Order: 1 · Live

Browser-based property-management software for Tanzanian landlords and managing agents. Multi-property workspace, automated TSh invoicing, M-Pesa / Tigo Pesa / Airtel Money tracking, renter self-service portal, bilingual EN/Swahili. The only product with a public live URL exposed (pms.bjptechnologies.co.tz).

BMS — Business Management System

Tagline: Run your whole business from one screen.  Slug: bms · Order: 2 · Live

An all-in-one ERP for Tanzanian SMEs — POS, multi-warehouse inventory, invoicing, purchases, accounting, reports, CRM and HR — with mobile-money payments built in. Live URL kept private; demo requests route through the BJP contact form.

Vikundi — VICOBA Management System

Tagline: VICOBA, finally without the cashbox.  Slug: vikundi · Order: 3 · Live

A complete management system for VICOBA savings groups and informal microfinance circles. Member register, contributions, loans, fines, social/funeral fund, M-Koba reconciliation, audit trail. Ships with honest-tone notes about single-group-per-installation and the proportional (vs. automated) share-out, so the public page doesn't oversell.

Session 16 · Hotfix

Three production rendering bugs

Immediately after PMS deployed, the live site surfaced three independent bugs. All three diagnosed against the production URLs, fixed and regression-tested in one branch.

PR #70   fix(products): admin 500 + brand vars + CSP-blocked icons Merged

The three bugs

SymptomRoot causeFix
Admin 500 on /admin/products/product/ Django 6 hardened format_html to refuse zero-arg calls. show_contact_state called format_html('<span ...>✓ filled</span>') with no placeholders → TypeError. Switched to mark_safe (no user input to escape). Added admin-client changelist test as a regression catch.
Hero / navbar unstyled on Products + Services + Industries CLAUDE.md §4 documented BJP brand variables (--navy, --accent, etc.) but they were never actually defined in any loaded stylesheet. Inline gradients fell back to transparent — white banner, white navbar text became invisible against it. Added the full 11-variable :root block to bjp.css. Single point of definition. Also resolved the pre-existing services / industries hero issues.
Feature icons invisible on /products/pms/ Bootstrap Icons stylesheet loaded from cdn.jsdelivr.net — not in the site's CSP allowlist. Stylesheet blocked, glyphs never rendered. Dropped the BI CDN entirely. Migration 0003_remap_pms_icons remapped all 8 PMS feature icons to Font Awesome Pro, which is already loaded site-wide.

Decisions

Drop Bootstrap Icons rather than whitelist the CDN in CSP
Font Awesome Pro is already loaded site-wide and is the convention everywhere else. Tightening CSP is preferred over loosening it.
Migration 0003 updates the existing record instead of editing 0002
CLAUDE.md §6 — never edit an applied migration. Fresh installs run 0002 then 0003; end state is identical.

Session 18 · Final polish

Readable typography + BMS scope correction

Screenshots from production flagged that body text on the detail page felt "too small to read." Investigation revealed the root cause was deeper than typography: Luminos sets html { font-size: 10px }, so every rem-based font-size in the detail template was rendering ~10× smaller than intended.

PR #74   fix(products): readable typography + drop BMS Loans Merged

The Luminos rem-base bug

Original 0.95rem values were rendering as 9.5px, not 15.2px. Every typography commit before the root-cause fix only moved the needle from 10px to ~13px — still cramped. The final commit converted all rem font-sizes in detail.html to match Luminos's 1rem === 10px convention, verified via window.getComputedStyle.

Architecture

How the module is structured

Public surface

  • /products/ — list page (live products only)
  • /products/<slug>/ — detail page (live only; coming-soon → 404)
  • Sitemap entries — products:list + ProductSitemap for each product
  • Navbar tab + mobile sidebar entry
  • "Our Products" home-page strip above Services

Admin surface

  • Unfold-themed ProductAdmin
  • Sidebar entry first under Website Content
  • Collapsible fieldsets (Identity / Descriptions / Detail / CTAs / Contact / SEO / Assets / Advanced)
  • Status badge + contact-block indicator on the changelist
  • Bulk actions: Mark Live · Mark Coming-Soon

The Product model

Inherits BaseModel (UUID pk, timestamps). 25 user-editable fields cover the entire detail page without any per-product templates — the same template renders PMS, BMS and Vikundi by reading the database.

Adding a fourth product

No code changes required. Either (a) add it via Django admin and upload assets into static/images/products/<slug>/, or (b) write a data migration mirroring 0005_seed_bms_vikundi. The list view, detail view, navbar link, home page strip and sitemap all pick it up automatically once status="live".
